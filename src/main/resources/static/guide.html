GUIDE / 01
ПРАКТИКУМ ИЗ РЕПОЗИТОРИЯ

От запроса до зелёного деплоя.

Сначала почувствуй HTTP руками, потом посмотри, как тот же сценарий становится тестом, контейнером и частью CI/CD.

Правило лаборатории: намеренно ломать запросы можно. Реальные пароли, карты и персональные данные — нельзя.

Маршрут

На главной странице выполняй эксперименты сверху вниз. Не переходи к заказу, пока не сохранишь productId из ответа создания товара. Смотри на тело ответа, заголовки и время — именно это обычно превращается в баг-репорт.

401 и 403

401 Unauthorized означает «я не знаю, кто ты»: добавь Bearer-токен. 403 Forbidden означает «знаю, но роль не разрешает»: запрос к /api/admin/stats специально показывает различие.

PUT, PATCH и повтор

PUT принимает полное представление изменяемого товара. PATCH в этом сервисе меняет только stock. Один и тот же Idempotency-Key с тем же телом вернёт тот же заказ и не спишет склад ещё раз; с другим телом даст 409.

Git и Docker

Запусти ./mvnw verify, затем docker compose up --build -d и python3 scripts/smoke.py http://localhost:8080. В PR GitHub Actions проверит Java, Docker и настоящий HTTP. Render деплоит только после зелёных Check.

Материалы

Открой OpenAPI YAML, скачай Postman collection и local environment. Токены из примеров учебные и не должны попадать в коммиты.
